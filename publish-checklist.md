# Чек-лист публикации в репозиторий

Порядок действий перед тем, как контент уходит в репозиторий.

## Перед публикацией
- [ ] Оффер сверен с карточкой аудитории (`audiences/`) — написан под боли, а не общо
- [ ] Формат соответствует площадке (таргет/контекст/SEO) — см. `templates/`
- [ ] Заголовок и текст в лимитах символов площадки
- [ ] CTA — конкретное действие, не «узнать больше»
- [ ] Цифры в оффере актуальны (срок, цена, порог) — не выдуманные
- [ ] Нет воды: «уникальный», «лучший», «профессиональный»
- [ ] Запись добавлена в `content-log.md` (дата, площадка, аудитория, статус)

## Нейминг файлов
- Формат: `[дата — опционально]-[тема]-[тип].md`
- Примеры: `2026-08-27-target-offers-q3.md`, `urlica-audience-card.md`
- Имена файлов — латиницей, lowercase, через дефис

## Commit
- Сообщение коммита короткое, по сути: `add: target offers for sellers`, `update: SEO page wholesale`
- Без `git push` и работы с remote без отдельного подтверждения
- Файлы выгрузок и конфиденциальные данные в репозиторий не попадают

## После публикации
- [ ] В `content-log.md` статус сменён на `опубликован` + дата
- [ ] Зафиксирована дата старта для последующей привязки метрик (CPL/CAC)
- [ ] Через 7–14 дней — сверка метрик по этому офферу, запись в колонку «Метрика-привязка»

## Что не делаем без подтверждения
- Не удаляем и не переименовываем файлы
- Не пушим в remote
- Не выходим за пределы рабочей папки проекта
